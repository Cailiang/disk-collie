# DiskCollie feature guide

[Home](../README.md) · [简体中文](FEATURES_ZH.md)

## The workspace

- **Overview:** a compact health gauge (green ≥80, amber 50–79, red <50) beside one device panel. CPU uses live samples, memory a segmented bar and storage a ring; the panel expands GPU, battery/power and network data. Metrics enter descending process lists or large files. Cumulative/daily charts count all successful cleanup bytes together, with item/session totals and no repeated recent list. Scores reflect available load/capacity readings, not hardware diagnosis.
- **Large files:** size, name and file-type filters over a compact native index. Scans ordinary files on the system drive; system locations, application data, credential directories and Trash are always excluded. Hidden personal directories can be included explicitly. Personal files move to the system Trash after review.
- **Duplicates:** expandable type → duplicate group → copy hierarchy; size → samples → complete BLAKE3 hashes. Defaults to files ≥10 MiB, which is also the minimum; scans the system drive with system locations, application data, credential directories and Trash always excluded; hidden personal directories are optional. Copies can be selected across groups and reviewed in one bottom action; every group retains a verified survivor before the batch starts. Hard links and cloud placeholders are excluded. At least one copy must remain, and contents are checked again before removal.
- **Space explorer:** expandable directory tree on the left, treemap on the right, and breadcrumbs. Scans the system drive, including Users on macOS, with hidden folders and application data excluded by default. The displayed totals reflect that scope; inclusion is optional. Folder picking is removed. The compact index has no two-million-item cutoff. Back to parent is explicit. The chart shows Top 10 + Other; Other opens subsequent groups, including paginated children. A minimum display area preserves ellipsized names and exact byte labels; the tooltip explains that tile geometry is adjusted for readability. Personal files and folders offer reviewed Trash actions; folder review includes hidden content and validates the complete tree before moving it. Scan roots, installed application locations, credential contents and excluded descendants block whole-folder removal; protected system/application files are visibly read-only. Reviewed project folders can include uninstalled `.app` dependency runtimes and build outputs, with framework symlinks captured without following their destinations. Packaged ASAR archives are reviewed as physical files, so Electron’s virtual archive metadata cannot cause false cross-volume rejections. Successful removals update every retained index and directory chart after success.
- **Privacy:** four categories → real application icon → profile → record type. Chromium/Firefox and accessible Safari history have local record previews; Locked Chromium stores are read through verified private temporary copies; WITHOUT ROWID related tables are supported. Chromium browsing, searches and downloads are cleaned separately with schema-preserving transactions. Browser accounts include cookies, site data, permissions, saved passwords and form history where supported; sensitive types, including local edit/recovery history, require explicit selection with lost-revision/unsaved-draft warnings, and previews never expose secret values. macOS includes SFL2/3/4 recent items, combined RecentHosts/RecentServers network history, Finder records, clipboard summary, shell history and scoped app/edit activity. All/hour/today/week filters use actual record timestamps; unsupported sources say All time only. Application activity hides actual zero-trace apps, retains unknown/permission counts and sorts by name or trace count in either direction. Default selections are empty; running browsers must be closed or explicitly skipped. Source-file size and trace count are separate from measured freed bytes. Bookmarks, downloaded files and original documents are preserved.
- **Application manager (Utilities):** a startup-warmed, persisted local inventory with actual OS logos, sizes and last-use metadata, bidirectional name/last-use/size column sorting, update/unused filters, Open, Check updates, concurrent per-app Update and Ask AI. An updating row alone shows progress; same-app update/uninstall operations exclude one another, and concurrent checks cannot restore stale results. User/System tabs keep their lists separate; User is the default and includes DiskCollie itself, protected from self-removal; System offers no uninstall action; missing usage is shown as unknown. macOS uninstall details show paths, sizes, rebuildable/personal-data labels and expandable children. Related data is optional; an app stays removable when no extra data is found or size measurement fails; the complete app is required, and selected parent/child paths are deduplicated. Updates reuse Homebrew Cask, App Store and Sparkle adapters. Windows/Linux use system tools for package management.
- **Processes:** user-only and CPU descending by default, actual icons, sortable headers, scope/search/pause and inline actions with tooltips. CPU/memory >40% is orange; >65% is red. Interacting freezes row positions. macOS app-helper termination targets its owning app and verifies exit, protecting system/self processes and reused PIDs.
- **Startup optimization (Utilities):** groups startup registrations by their verified application/executable identity, with search, enabled/disabled/leftover filters, source/trigger/path details, a system-item filter, per-source or grouped enable/disable, and explicit removal of startup registrations. Configured and running states remain distinct; unknown or unreadable sources remain visible. Read-only discovery reports partial coverage and access guidance. Changes use main-owned IDs, snapshot checks and readback, and persist in the local maintenance ledger. AI explanations use the existing user-configured model.
- **Cleanup advisor:** explains file ownership, whether cleanup is suitable, its impact and recovery limits, and size-based priorities. Start a question from scan results or the focused landing page. Visiting the page does not scan; submitting a question collects evidence. Provider setup preserves the draft and a direct return. The execution rail appears only for a real plan. Your own provider/model, registered operations and explicit confirmation remain required; credentials stay encrypted locally.
- **Local statistics / Settings:** cleanup records share the embedded `disk-collie.sqlite` database with encrypted providers, custom app settings, AI conversations and the maintenance ledger. Legacy cleanup JSON is imported once without duplicating records. Settings provides an add/remove list of scan-excluded folders, applied before traversal across file/privacy workspaces; changes invalidate old indexes and cleanup plans. Model setup defaults to custom OpenAI-compatible: name, address, key, explicit model fetching, selection and save. Official addresses are fixed and concise help is behind a question mark.

Operation outcomes and errors use a centered, persistent dialog instead of page-top alerts or transient toasts. Concurrent notices queue and deduplicate; acknowledgement or Escape closes them and restores focus. Scan progress remains inline.

Useful cleanup explanations live behind small transparent Help glyphs; Overview, Applications, Processes, AI history and Space explorer omit redundant help. Data pages use compact toolbars and rows. Results, filters and selections stay available across page and AI navigation. Large files use a “Delete selected items” batch action that opens one confirmation and moves the selection to Trash immediately after confirmation; duplicates use a bottom batch-action bar; privacy adds record counts, source size, selection modes and one confirmation. The AI task launcher lives in the top bar. Independent file/privacy work runs concurrently; same-scope jobs and all mutations remain ordered, with scoped cancellation and at most two heavy scans. Removals during scanning/hashing are reconciled before results are published. Scan labels distinguish storage analysis, large-file discovery and duplicate discovery. Each file/directory row offers Show in folder and Ask AI; selecting a file or opening a folder in the Space explorer map or tree highlights that item, while Show in folder, Ask AI and reviewed Trash actions stay in the directory rows. Asking opens a dismissible task panel anchored below the top bar while retaining the source; buttons show progress/success and unread results stay visible. Missing providers pause tasks until saved. Results and setup retain a direct return to the original page, including scroll. Tasks support cancellation and retry; the task panel is session-local and completed conversations persist in history. Cleanup animates actual processed-item progress and returns to the remaining results, removing only confirmed successes.

Application inventory starts in the background on launch. The list appears before recursive size measurement, is restored across launches and refreshed by install-directory watchers plus a five-minute check. Unchanged app sizes are reused. Refresh preserves stable IDs and valid file selections; restored cache entries must be live-registered before actions. macOS size measurement uses a separate worker and an eight-second per-bundle limit.

## Stack and platforms

The package is `disk-collie`, the application identifier is `com.fcl.diskcollie`, the native sidecar is `disk-collie-engine` and installers use `DiskCollie-<version>-<arch>`. New profiles live under `DiskCollie` in the platform application-data directory, using `disk-collie.sqlite`. First launch copies an old Memento profile with a consistent SQLite snapshot and its encryption key, retaining providers, settings, conversations and cleanup totals. The old profile is preserved and existing DiskCollie data is never overwritten. Explicit custom profiles stay isolated. Legacy database names, protected folders, terminal markers and game-score keys remain recognized. Updates use the new repository; until its first release, the installed version is reported as current.

Electron + React + TypeScript provide the shell and existing model integrations. An independently implemented Rust sidecar owns read-only indexing, metadata aggregation, duplicate verification and portable system inspection. macOS uses `getattrlistbulk` with a standard traversal fallback; Windows batches directory metadata and file IDs; below-threshold files avoid per-file handle queries, while retained candidates and removal checks retain strict inspection. Unsupported filesystems fall back to standard traversal. Linux uses bounded parallel native traversal. Each scan purpose retains its own session; directory and large-file queries reuse that session and are paginated. Successful removals reconcile all retained indexes without a new scan. Hidden explorers exclude removed ancestors and descendants before reloading their tree, returning to the nearest surviving folder after app/config uninstall. Removal progress uses file-operation waiting text and uninstall progress, rather than scan queue labels.

macOS, Windows and Linux adapters and x64/arm64 packaging are configured. macOS x64 is locally runtime tested. Windows native code is also cross-compile checked locally; Windows/Linux runtime verification is assigned to the three-OS CI workflow. macOS terminal/startup/service internals remain platform-specific. See the capability matrix and validation boundaries in the architecture document.

## Develop and verify

Requires Node ≥22.13, npm and Rust ≥1.88. Packaging needs the target platform toolchain; macOS packages require the project Developer ID.

```sh
npm ci
npm run dev
npm run dev:web -- --port 4178
npm test
npm run native:test
npm run build
npm run scan:smoke
npm run electron:smoke
npm run ui:smoke -- http://127.0.0.1:4178
```

The browser preview uses explicit demo data and is labeled **Demo workspace**. The packaged app always uses the local IPC/native engine; it never substitutes demo results on errors.

Language catalogs are in `src/shared/locales`. Add a catalog and register its locale in `src/shared/localization.ts`. The language selector and settings validation follow that registry. Catalog parity and interpolation are tested; missing keys fall back to English. Dates and numbers use `Intl`.

## File operations

The Renderer sends IDs, never mutation paths or shell commands. The main process checks selection scope, generation, registered identity and path components again. Personal files and app bundles go to Trash; narrowly scoped caches/history are permanently removed only after a separate confirmation. System/app-data directories are protected in the large-file browser. Cleanup records report processed bytes as estimates; they do not claim newly available disk space. Local scans do not upload file contents. Asking the AI sends the existing compact maintenance context and the selected file’s path, size and available modification time to your configured provider; this explanation does not read file contents.

DiskCollie remains MIT licensed. MangoDisk was studied as a GPL-3.0 reference; its source and assets were not incorporated.

Privacy previews stay local. Ask AI sends only source/type/count/risk/range metadata, never the previewed URLs, searches, commands or credentials. Safari currently supports history, sessions and cache, not separate search/download/account stores. Windows system activity covers explicit Recent shortcuts; Jump Lists, registry and clipboard history are not yet supported. Permission failures remain visible and can open system access settings.

Cleanup history is no longer a sidebar destination or an Overview shortcut. The embedded ledger still drives cumulative/daily charts; assistant task history is reached from the AI page. Long application updates run independently from storage mutation lanes; package managers can enforce their own installation locks, reported as per-application failures.

The application icon, startup, sidebar and advisor use the approved left-facing, upright-eared border collie with a confident, playful expression. The vector mark and scan-game character follow the selected theme. Scan pages offer three opt-in games: Hurdle run, Frisbee catch and Pond hop. Space (or click/tap) starts, jumps, resumes and retries; holding Space does not repeat jumps. Frisbee catch has no time or miss limit: a missed formation only resets the streak, preserving score and continued play; its HUD shows catches instead of remaining lives. Runner and Pond hop still end on collisions. Hidden views pause, local best scores persist, and reduced motion removes decorative movement. Native progress/cancellation stay available and scan completion immediately shows results. Obstacles are drawn from a shuffled pool, with ten runner shapes including one/two/three-log groups and low/overhead birds, varied frisbee flight paths and pond formations. Patterns unlock with distance; speed, spacing, treats and catch streaks vary play. Four scrolling landscapes crossfade along the route, with layered parallax and an independent day/night cycle using theme colors. Scene and lighting selectors can override automatic progression, with a distinct nighttime palette; changing scenery pauses play without resetting the round. The camera adapts to the actual canvas size and pauses on window resize, preserving score and obstacles. Terminal optimization uses the same three-game scan panel as the other workspaces and omits empty counters/results during the first scan. Canvases fill the available height in normal and fullscreen windows; controls stay separate from the scene and results return immediately when scanning ends. Passive pet stories have been removed. Each navigation entry retains its distinct semantic icon, and Settings uses spacing instead of horizontal separators. See [Mascot assets](MASCOT_ASSETS.md) for sources and exports.

## Startup source coverage

macOS covers user/global LaunchAgents, LaunchDaemons, System Events login items, the Background Task Management catalog and registered app helpers. Launchctl override states take precedence over plist defaults; loaded-but-idle jobs remain enabled without being labeled running. Launch aliases are fingerprinted with their physical target, and removal affects only the alias. Legacy login items retain their hidden setting when disabled/restored. Modern system-managed background/helper registrations open system settings. DiskCollie’s own registration is managed through its Settings.

Windows reads user/machine Run and RunOnce across applicable registry views, Startup folders and shortcut targets, boot/login scheduled tasks, automatic/disabled services, packaged startup tasks and advanced system autorun settings. Supported Run/folder controls preserve the registration and use configured approval state; RunOnce is shown with removal support. Protected services, policy/system entries and packaged tasks stay read-only where supported public controls are unavailable. Machine changes request Windows authorization. Linux reads XDG autostart and user/system systemd services; global desktop entries get current-user overrides, and protected system units remain read-only.

Source enumeration is bounded and read-only. Unavailable permissions, invalid formats or unsupported settings do not become invented empty or disabled results. Startup changes take effect according to the native trigger and do not immediately stop running processes. Removing a registration preserves executables and personal files. Every change rechecks the selected definition and verifies the resulting state; the Startup operation history records only verified outcomes, separately from reclaimed storage statistics.

Native null placeholders are omitted from startup names/publishers. Bundled helper files alone are not startup registrations. Unavailable states explain the system limitation; groups with enabled sources retain that evidence. Displayed snapshots survive idle time and read-only rescans; changes still validate the originally selected definitions.

App updates check GitHub about three seconds after launch and hourly. GitHub version/manifest/download network failures fall back to https://diskcollie.app/releases/latest.json and the /updates/ feed, with verified local payload mirrors. Integrity errors remain errors. Downloads require an explicit install/restart click; normal quit does not install.
